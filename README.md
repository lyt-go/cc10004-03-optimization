# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts         本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/orchestration-service.ts 渠道投产编排：停用回收、预算释放、并发版本
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化 / 回收模型
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

### 渠道投产编排（`/orchestration`）

渠道停用后的投产回收以这个页面为业务入口（渠道管理页的「停用渠道」也会自动生成队列）：

1. **生成待回收活动**：只取该渠道下「投放中」的活动，草稿与审批中活动不进入回收队列。
2. **按三种结论拆分**：结束日期不晚于停用生效日 → `已结束`；距结束不超过人群待暂停边界
   → `待暂停`（保留已完成记录，不直接丢数）；其余 → `仍在采集`（状态不变，只撤销新增准入）。
3. **重算额度**：渠道预算池减去已释放额度，按结束日期先到先得分配；释放金额只算尚未消耗
   的预算，已消耗部分永远不释放。
4. **阶段单向**：`待回收 → 回收中 → 已提交 → 已归档`，不允许回退或跳级；中断后可从未完成
   的活动继续，每次判定都写一条「回收依据」。
5. **原子提交**：活动结束/暂停、渠道占用退出、释放台账和依据在同一次 `localStorage` 写入里
   同时成立，不存在只释放一半预算或只结束一半活动的中间态。
6. **并发版本**：同一渠道以停用生效时刻较早的版本为准，后到的晚版本直接归档并被取代，
   操作人看到的是已处理结论而不是重复回收。

验收样例：`CHAN-0003` 停用后，`CAMP-0003` 进入待暂停并在活动排期显示回收来源，
`CAMP-0004`（结束日期早于生效日）判为已结束，`CAMP-0005` 仍在采集；提交后渠道投产清单
显示释放金额，草稿 `CAMP-0001` 不受影响。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.tsx`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`；渠道投产编排走 `frontend/src/api/orchestration-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`；回收领域模型（阶段、判定、额度分配）在 `frontend/src/data/recovery.ts`。
- 状态流转只允许在服务层里改，页面组件不做业务判断；已归档/已停用/已结束等终态不提供回退动作。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。
